# TDD-аудит PDM

Дата проверки: 17 сентября 2026 года.

## Итоговая оценка

Проект уже имеет сильный набор регрессионных и интеграционных проверок, но исторически они были разрознены и не запускались одной командой. После аудита критические автоматизируемые сценарии объединены в `npm run test:critical`.

Текущий уровень зрелости: **B**. Критические переходы состояния, восстановление PowerPoint, сцена, интерфейс и стриминг проверяются хорошо. До уровня A не хватает аппаратного стенда и длительных нагрузочных прогонов с реальными дисплеями, камерами, аудиоустройствами и Stream Deck.

## Что покрыто автоматически

- PPTX: единичный экспорт, дисковый кэш, повторное использование, ранний старт после 25%, портретные пропорции, миниатюры, ошибки экспорта и очистка при завершении.
- PowerPoint: очередь команд, подтверждение закрытия, ограниченные повторы, защитная заставка, восстановление после переподключения дисплея и безопасность чужих документов Office.
- Сцена: фон, черновик/эфирный снимок, порядок слоёв выше/ниже, PDF/PPTX разных пропорций, QR, текст, таймер, камера, хромакей, видео и очистка ресурсов.
- Таймер: запуск из Stream Deck включает вывод, пауза его не скрывает, переход в отрицательное время остаётся видимым, сброс и владелец `toolbar/scene` сохраняются корректно.
- Stream Deck: нормализация конфигурации, подписи и цвета клавиш, защита HTML, выбор каналов, старт видео, сцена, титры по выступающему, QR, таймер и музыка.
- Панель управления: обе редакции, классический вид и Broadcast Pro, ширины 1280/1024/900/880, скрытие кнопок без остановки фоновых процессов, модальные окна поверх служебных элементов.
- Обучение: полный 31-шаговый сценарий на реальном интерфейсе.
- Стриминг: BGRA/PCM → FFmpeg, переподключение приёмников, ограничение очереди, очистка процессов, рукопожатие, отбрасывание устаревших кадров и независимые ключевые сегменты для `libx264` и `h264_qsv`.
- Сборки: Standard без FFmpeg и Stream с FFmpeg.

## Найдено во время аудита

- Классическая верхняя панель могла выходить за границу окна при ширине 880 px. Добавлены `width: 100%` и `min-width: 0`; повторный UI-прогон прошёл.
- Команды Stream Deck, выбор реального канала сцены и внешние команды таймера находились внутри React-компонентов и почти не поддавались прямому тестированию. Критические решения вынесены в чистые функции и покрыты регрессиями.
- Старые тесты не имели единого запуска. Добавлены группы `core`, `ui`, `integration` и общий fail-fast раннер.

## Что остаётся проверять на реальном стенде

- физическое отключение/подключение Stream Deck XL, удержание и быстрые серии нажатий;
- горячее отключение/подключение эфирного монитора во время показа PowerPoint;
- реальные камеры, SDI/USB-платы захвата, смена форматов и потеря сигнала;
- конкретные RTMP/RTMPS-площадки, нестабильная внешняя сеть и неверные ключи;
- реальные аудиоустройства, мастер-звук, задержка и синхронизация губ;
- многочасовой прогон с большими PPTX/PDF/видео и наблюдением за памятью/GPU;
- визуальная оценка читаемости и цветопередачи на эфирном дисплее.

Это не пробелы модульных тестов: без аппаратуры и внешних сервисов такие проверки нельзя сделать достоверно. Их стоит оформить отдельным чек-листом перед релизом.

## Команды

```powershell
npm run test:critical
npm run test:critical:core
npm run test:critical:ui
npm run test:critical:integration
```

`test:critical` запускает 20 критических групп. Тесты захвата реального дисплея и измерения задержки оставлены отдельными, потому что они требуют свободного дополнительного монитора:

```powershell
npm run test:streaming:capture
npm run test:streaming:latency
```
