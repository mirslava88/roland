# Строгая типизация PDM: 23 сентября 2026

## Исправления

Исходная проверка двух реальных TypeScript-проектов выдавала 111 диагностик: 9 в main и 102 в renderer. Из них 83 относились к одному потерянному сужению типа `channel.file` после замены канала. Это не 111 независимых ошибок исполнения.

- TAKE хранит проверенный снимок непустого канала; проверка пустого канала и существующие проверки отмены/замены источника сохранены.
- Нативные таймер, QR и верхние медиаслои сравнивают ID с `screen.getPrimaryDisplay().id`. У объекта Electron Display нет поля `isPrimary`, используемого в собственном renderer DTO.
- Стрим и внутренний видеовыход виртуальной камеры получают BGRA через `NativeImage.toBitmap()`, а не устаревший alias `getBitmap()`.
- Импорт `.pdmconfig` восстанавливает `contentChannelId` только для существующего непустого канала. Для старого файла настроек или отсутствующего материала используется `null`; Сцена остаётся выключенной.
- Исправлены типы data-атрибутов кнопок, обязательность подписи Stream Deck, сужение типа пункта контекстного меню и разделителя слоёв, nullable DOM-редактора, параметров открытия PDF/эфирного окна, частичных обновлений видеотранспорта, props обучения и аргументов PowerPoint.

`strict` не отключён, `tsconfig` не ослаблен. Подавления `@ts-ignore` и принудительные приведения для сокрытия диагностик не добавлены. Исправления выполнялись поверх существующей незакоммиченной работы.

## Проверки

- `npm run typecheck` проверяет **оба** проекта: `tsconfig.node.json` и `tsconfig.web.json`. Обе проверки проходят без ошибок.
- `scripts/test-type-safety.cjs` исполняет проверки реальных IPC-обработчиков до создания окна на синтетических Electron Display без `isPrimary`; проверяет смену основного дисплея, порядок слоёв, реальные сохранение/загрузку конфигурации и частичные обновления видео в изолированном store.
- `scripts/test-virtual-camera-frame.mjs` использует настоящий Electron NativeImage: 16:9, вертикальный кадр, 4:3, широкий кадр и увеличение малого кадра. Проверяются длина BGRA, цвет, незеркальная ориентация, пропорции, чёрные поля и отклонение пустого кадра.
- Существующие 17 управляемых сценариев гонок проходят; мок кадров стрима использует тот же `toBitmap`, что рабочий код.

Проверка типов обязательна перед обычной сборкой, обеими редакционными сборками и упаковкой; GitHub release workflow использует тот же редакционный сценарий. Она также включена в общий критический набор, теперь содержащий 25 групп. Vite-транспиляция больше не является единственным барьером для ошибок типов.

Полный `node scripts/test-critical.mjs all` прошёл **25/25 за 303 секунды**: обе production-сборки, 32 шага обучения, Scene audio/video UI, GPU-хромакей и FFmpeg с libx264/h264_qsv. После него прошла обычная Stream-сборка через `npm run build`, включая новый обязательный typecheck. В Scene UI остаются сообщения тестового синтетического ввода `setPointerCapture: No active pointer`; assertions и завершение всей группы успешны.

Проверки типов и автоматизированные сценарии не доказывают отсутствие любых аппаратных сбоев: физическое HDMI/USB-переподключение и изображение удалённого ВКС требуют отдельных проверок. Коммит, релиз и push в этой работе не выполнялись.
